# Події Chronos: CRUD, повторення та email-учасники

## Права доступу

- `viewer` (або вищі ролі) може читати події. `editor`, `admin`, `owner` можуть створювати, редагувати та видаляти події.
- Для API-ключів читання вимагає `calendar:read`, а мутації — `calendar:write`. Для роботи з чужим календарем потрібен чинний integration grant відповідного рівня.
- Публічні `CalendarLink` підтримують **лише читання списку подій** `/api/calendar-share/events`. Жодного створення, редагування або видалення через посилання немає.

## Ендпоїнти

| HTTP | Шлях | Призначення |
| --- | --- | --- |
| GET | `/api/calendars/:id/events?from=...&to=...` | Список подій + повторення, пагінація `page`/`limit` |
| POST | `/api/calendars/:id/events` | Створення події |
| GET | `/api/calendars/:id/events/:eventId` | Одна збережена подія / базова серія |
| PATCH | `/api/calendars/:id/events/:eventId` | Редагування події / усієї серії |
| DELETE | `/api/calendars/:id/events/:eventId` | Видалення події / усієї серії (204) |
| GET | `/api/calendar-share/events?from=...&to=...` | Перегляд подій за публічним токеном, без мутацій |

Усі мутації потребують авторизованої сесії (або API-ключа з відповідними правами). Тіло JSON обов'язково валідовується. `PATCH` не дозволяє змінювати `type` чи `calendarId`.

## Типи подій

- `arrangement`: `type`, `title`, `startsAt`, `endsAt` (строго після початку); `status` — `scheduled` / `canceled`; необов'язково `locationUrl` (лише HTTP(S)).
- `task`: `type`, `title`, `deadline`; `status` — `todo` / `in_progress` / `done`.
- `reminder`: `type`, `title`, `remindAt`.
- `holiday`: `type`, `title`, `date` (YYYY-MM-DD), `internationalName`.

Спільні поля: `description`, `color`, `categories` (масив до 20), `attendees` (масив до 50 email), `isRecurring`, `recurrenceInterval`, `recurrenceEndDate`. Відсутні необов'язкові поля зберігаються з дефолтами моделі. Сервер повертає для кожного учасника `email`, `inviteStatus` та `expiresAt`, але **не розкриває inviteToken**.

Приклад створення:

```json
{
  "type": "arrangement",
  "title": "Командна зустріч",
  "startsAt": "2026-12-01T10:00:00Z",
  "endsAt": "2026-12-01T11:00:00Z",
  "status": "scheduled",
  "attendees": ["team@example.com"],
  "isRecurring": true,
  "recurrenceInterval": "weekly",
  "recurrenceEndDate": "2027-02-01"
}
```

## Повторення

- Підтримано `daily`, `weekly`, `monthly`, `yearly` з необов'язковою датою завершення включно.
- Occurrence **генеруються під час читання**, вони не створюють копій у MongoDB і не потребують фонового cron.
- Кожне повторення має **оригінальний `id` серії** та унікальний `occurrenceId` (`<seriesId>@<ISO UTC datetime>`). `startsAt` та похідні дати відображають саме це повторення. `GET/:eventId` повертає базову серію.
- Повторення зберігають локальний час початку календаря з урахуванням IANA timezone та DST. Для місячних повторень 29–31 числа, відсутнє число у коротшому місяці замінюється останнім днем цього місяця; для 29 лютого річні повторення в невисокосні роки — 28 лютого.
- Без `from/to` сервер використовує обмежене вікно від **30 днів тому до 90 днів уперед**; якщо задано лише одну межу, друга додається з інтервалом 90 днів. Максимальна тривалість `370` днів і `25 000` occurrence у відповіді до пагінації, щоб не перевантажувати сервер. У frontend вибраний діапазон завантажується повністю з пагінацією (до 10 000 occurrence).
- Операції PATCH / DELETE змінюють **цілу серію**. Винятки для конкретних дат, редагування окремого occurrence, прийняття / відхилення учасником, листи-запрошення та токени ще **не реалізовані**.

## Frontend

- На сторінці календаря доступні month та agenda. Натискання на подію відкриває деталі та email-учасників.
- Кнопка «Нова подія» й дії редагування / видалення доступні лише editor/admin/owner.
- Форма перемикає обов'язкові поля за типом події, містить часовий пояс календаря, масив email, категорії та параметри повторення.
- Повідомлення про помилки, назви полів, назви інтервалів — українською та англійською.

